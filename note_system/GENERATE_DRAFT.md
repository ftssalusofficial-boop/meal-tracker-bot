# 実行指示：note記事の下書きを1ヶ月分まとめて生成する

このファイルは、月次の定期実行タスク（スケジュール）またはユーザーの指示によって呼び出されたときに実行する手順書。**1回の実行で複数本（デフォルト6本 ≒ 週1〜2本ペース1ヶ月分）をまとめて生成し、まとめてコミット・プッシュする。**

## 前提として読み込むファイル
- [business_profile.json](./business_profile.json) — 事業・ターゲット・トーン
- [content_strategy.md](./content_strategy.md) — コンテンツ方針・入口キーワード/フォーマットの型・CTAテンプレート・タグ運用・エビデンス方針（**特に§7を必読**）
- [content_calendar.json](./content_calendar.json) — 入口キーワード/フォーマットの使用状況・過去記事一覧
- [past_articles.json](./past_articles.json) — 既存記事一覧（重複回避・トーン参考用）

## 重要な前提（方針）
このアカウントは「自律神経から整える施術者」という特化ブランディングが核。**自律神経というテーマ自体は変えない。** 重複を防ぐのは、入口キーワードと説明フォーマットの組み合わせを毎回変えることによる（詳細は content_strategy.md §3〜5）。

## 生成本数
デフォルト **6本**。ユーザーから別の指定があればその本数に従う。

## 手順（1本ごとに繰り返す）

1. `content_calendar.json` の `entry_keywords.priority_unused` と `formats` の使用回数、および**このバッチ内で今回すでに使った組み合わせ**を確認し、以下を満たす組み合わせを1つ選ぶ：
   - 入口キーワード：`priority_unused` から1つ（無くなっていたら `used` の中で `count` が最小のものから選ぶ。「睡眠・だるさ」は count が高いので当面避ける）
   - フォーマット：`used_count` が少ない/0のものを優先（G, H, A, D, E, Fを優先。B, Cは控えめに）
   - `used_topics` の直近3本、および**今回のバッチ内で既に生成した記事**と同じキーワード×フォーマットの組み合わせにならないことを確認する（バッチ内で6本とも異なる組み合わせにする）
2. **エビデンス調査（WebSearchツールを使用）**：
   - 記事の切り口に関連する生理学・自律神経・整体/トレーニング分野の情報を、信頼できる情報源（学術機関、医療機関、査読論文、公的機関の情報等）でWebSearch/WebFetchを使って調べる。
   - 実在する研究・データを見つけて引用する場合は、検索結果のURLや出典名を記事内に明記する（例:「〜という報告があります（出典：◯◯）」）。
   - 検索しても裏付けが取れない、または情報源の信頼性が低いと判断した場合は、**創作せず**一般的に確立された生理学の知識の範囲に留めるか、該当箇所を `[要出典確認]` とマークし、記事メタ情報に `needs_fact_check: true` を追加する。
   - 検索自体が失敗した/使えなかった場合も同様に、断定を避けた一般的な書き方に留める。
3. [content_strategy.md](./content_strategy.md) の「本文構成」「CTAテンプレート」「タグ運用」「やらないこと」「エビデンス・ファクトチェック方針（§7）」に厳密に従い、note投稿用の記事を作成する。
   - タイトルには選んだ入口キーワードを必ず含める。
   - 本文は必ず自律神経の視点に接続する（施術者としての専門性・差別化の核のため）。
   - 効果を保証する表現は使わない。「個人差があります」等の前提を自然に含める。
   - 本文末に必ずCTAブロックを入れる（テーマに合わせて1文目のみ調整可）。
   - 文字数目安 2,500〜4,000字。
   - 記事末に推奨タグ一覧を記載する。参考にした出典があれば「参考情報」として記事末にURL/出典名を列挙する。
4. 生成した記事を `note_system/drafts/YYYY-MM-DD_slug.md` として保存する（`YYYY-MM-DD` は実行日、`slug` はタイトルから短い英数字スラッグを作る。バッチ内で連番や内容が分かる別々のslugにする）。ファイル冒頭に以下のメタ情報を含める。
   ```
   ---
   title: <タイトル>
   entry_keyword: <選んだ入口キーワード>
   format: <選んだフォーマット（例: G_トレーニング接続系）>
   needs_fact_check: <true/false>
   sources: <参照した出典URL。無ければ空>
   status: draft
   created: <実行日>
   ---
   ```
5. `content_calendar.json` を更新する（1本生成するたびに）：
   - `used_topics` に今回の記事を追記（title・keyword・format・date・source: "自動生成（月次バッチ）"）
   - 該当する `entry_keywords.priority_unused` からキーワードを削除し、`entry_keywords.used` に追記（countは1、または既存があればcountを+1）
   - 該当する `formats.<format>.used_count` を+1

## 全本数の生成が終わったら
1. `content_calendar.json` の `last_generated` を実行日に更新、`generation_count` を生成本数分加算する。
2. 生成した全ファイル＋更新済み `content_calendar.json` をまとめて1回のコミットでコミット・プッシュする（ブランチ: main）。
3. ユーザーに完了報告をする。報告には以下を含める：
   - 生成した本数と各記事のファイルパス・タイトル・入口キーワード・フォーマット
   - `needs_fact_check: true` の記事があれば、その一覧と該当箇所を明示し、「投稿前に必ず内容を確認・裏取りしてください」と伝える
   - 出典を明記できた記事があれば、その出典も報告に含める
   - 「内容を確認のうえ、問題なければnoteに手動で投稿してください」という一言
   - 全記事にCTAブロックが入っていることの確認

## 重要な制約
- **note.comへの自動投稿・自動ログインは行わない。** 生成するのはあくまで下書きファイルであり、投稿はユーザーが手動で行う。
- バッチ内・直近履歴を通じて、同じ入口キーワード×フォーマットの組み合わせを繰り返さない。
- 実在確認できない研究・統計を創作しない（content_strategy.md §7）。WebSearchで裏付けが取れないものは一般論に留めるか `[要出典確認]` を付ける。医療的な断定表現、誇大な効果保証は書かない。
