# SALUS note運用システム

SALUS（東京23区・出張パーソナルトレーニング＋整体）の新規集客用noteアカウントを、下書き自動生成と評価・改善提案の両輪で運用するための仕組み。

## 構成
- `business_profile.json` — 事業・ターゲット・トーンなどの基礎情報
- `content_strategy.md` — コンテンツ方針（ピラー・タイトルの型・CTA・タグ運用）
- `content_calendar.json` — ピラーのローテーション状態・ネタ候補・使用済みトピック
- `past_articles.json` — 運用開始時点の既存8記事の記録
- `analytics_log.csv` — アナリティクス数値の履歴ログ
- `GENERATE_DRAFT.md` — 下書き生成の実行手順（スケジュール実行 or 手動指示で使用）
- `EVALUATE_ACCOUNT.md` — 運用評価・改善提案の実行手順（ブラウザでのログイン確認が必要なため手動トリガー推奨）
- `scripts/diagram_helpers.py` — 記事に挿入する説明図（比較図・タイムライン等）をmatplotlibで生成する共通部品
- `assets/fonts/` — 図解で使う日本語フォント（M PLUS 1p）。クラウド実行環境でも同じ見た目にするために同梱
- `drafts/` — 生成された下書き（.md）の保存先
- `drafts/images/` — 記事に挿入する説明図（.png）の保存先

## 使い方

### 下書きを生成したいとき
Claude Codeで次のように依頼する：
> `note_system/GENERATE_DRAFT.md` の手順でnote記事の下書きを作って

**月次バッチ方式**：毎月1回、まとめて6本（週1〜2本ペース1ヶ月分・デフォルト値）を一気に生成するよう、スケジュールタスクとして登録済み（詳細は下記）。各記事はWebSearchで内容を裏取りしながら生成し、具体的な症例パターンを最低1つ入れる（content_strategy.md §5.5）ことで、内容が一般論だけで薄くならないようにしている。さらに記事ごとに1〜2枚、比較図やタイムラインなどの説明図（`drafts/images/`）も自動生成する。生成された下書きは `drafts/` フォルダに保存されるので、内容を確認してから手動でnoteに投稿する（画像もエディタから手動アップロード）。**自動投稿は行わない。**

### 運用を評価してほしいとき
ブラウザでnoteにログインした状態で、次のように依頼する：
> `note_system/EVALUATE_ACCOUNT.md` の手順で運用を評価して、改善案を出して

アナリティクス画面の数値を一緒に確認しながら、`analytics_log.csv` に記録し、改善提案をまとめる。

## 現状評価のサマリ（2026-09-06時点、v2）
- 記事8本・フォロワー0人。CTA不在が課題の一つ。
- 「自律神経特化」は運営者の意図的なブランディングであり**維持する**。実際の重複問題は入口キーワード×説明フォーマットの組み合わせの被り（特に「睡眠・だるさ」テーマの3連続）。
- 今後は自律神経の視点を保ったまま、入口キーワード（肩こり・猫背・冷え 等）と説明フォーマット（タイプ診断・誤解を正す・トレーニング接続 等）を毎回変えて重複を防ぐ。記事末CTAによる公式HP（https://w-salus.com/）への導線も導入済み。
- エビデンス面は、AIが実在しない研究を創作しないよう `content_strategy.md` §7に厳格なルールを設定。`needs_fact_check: true` の記事は投稿前に必ず人の目で裏取りする。
- 初回の月次バッチ生成後、「内容が薄い」というフィードバックを受け、具体的な症例パターンの必須化・ヘッジ表現の使い回し禁止（§5.5）と、説明図の自動挿入（§9.5）を追加した。
- 詳細は `content_strategy.md` を参照。
